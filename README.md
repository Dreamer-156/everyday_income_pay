# 收支簿 · 第一版

在 Windows 本机导入微信、支付宝和银行卡账单，核对自己的账户转移，再查看月度收入、净支出和结余。只监听 127.0.0.1，不连接支付账户。导入、统计和本地分析均在本机完成；模型分析仅在用户预览并确认发送后调用外部接口。数据文件本地保存，未做数据库加密。

## 使用

1. 首次下载：先按下方“手动启动”中的命令创建 .venv 并安装 requirements.txt，再双击 install-background.cmd 安装当前用户的后台任务。此电脑已有 bundled Python 和后台任务，可直接双击 start-ledger.cmd。日常双击本目录的 start-ledger.cmd。浏览器会打开本机页面。后台服务由 Windows 管理，启动窗口退出、关闭浏览器或 Codex 不会停止服务。
2. 在“账户与规则”登记自己的银行卡。名称和别名应与账单文字一致，尽量使用银行和尾号，例如 招商银行(1234)。只登记自己的账户。
3. 在“导入账单”选择渠道、账单所属账户，再选择或拖入文件。微信、支付宝账单分别选对应钱包；银行账单选具体银行卡。支付方式字段另存实际扣款卡。
4. 核对表头行、字段和前 5 条记录，再确认导入。报告会列出新增、重复和错误行。
5. 在“待确认”处理疑似转移、重复记录和收支方向未知的记录。点击“核对”可以改类型、分类和备注，或通过记录编号关联另一条流水。
6. 在总览或流水选择月份；“全部月份”取消月份筛选。CSV / Excel 导出按月份范围导出完整流水，包括被排除的记录及排除原因，不使用搜索和分类筛选缩小导出。

页面左下角的“演示账本”使用独立数据，不会混入自己的账本。演示账单都在 examples 中，均为虚构数据。

## 支持与限制

- CSV、TSV、TXT 分隔表格、未加密 XLSX 和带文字层的 PDF 表格；自动识别常见中文列名、账单前言，支持选择工作表和手工列映射。
- 支持 UTF-8、GB18030、UTF-16；日期支持 YYYY-MM-DD、YYYY/MM/DD 和常见带时间格式。
- 支持单一金额加收支方向、负数表示支出，以及独立的收入金额／支出金额两列。正金额没有方向时不会假定为收入。
- 单文件上限 20 MB、十万行，XLSX 展开后上限 100 MB。
- 第一版只统计人民币；若币种列明确为外币，错误报告中会拒绝该行。无币种列的文件需用户确认是人民币。
- 不支持旧 XLS、扫描图片 PDF（当前无 OCR）、加密 XLSX、压缩包、自动登录或实时同步。请先解压账单；旧 XLS 可在 Excel 中另存为 XLSX。分开的日期与时间、特殊银行格式需先转换到模板。
- PDF 与不同银行的实际版式尚未逐一核验。自动测试和 PDF 浏览器预览使用模拟样本；实际导出格式有变化时，请核对笔数、合计与字段映射。
- 自动分类采用用户添加的关键词，不调用 AI；规则按添加顺序匹配，手工分类优先。

## 统计规则

金额统一使用整数“分”，避免浮点误差。

- 收入：外部进入自己的资金，例如工资、生活费、奖学金。
- 净支出：消费支出减退款；收支结余为收入减净支出，不是账户余额。
- 内部转移：充值、提现、银行互转、信用卡还款等，有明确转移类型且指向已登记本人账户时排除收支；只导入一端也可排除。未知接收账户的提现／充值进入待确认。
- 普通“转账”不会因付款来自自己的银行卡而被当作内部转移；给朋友转账仍保留支出。商户消费中的话费／游戏充值不会自动当作钱包充值。
- 配对转移：等额、不同本人账户、72 小时内、双方账户描述或共同订单引用匹配，且候选唯一时关联。仅金额和时间相近不会自动配对。金额不同时可手动确认，手续费需另有支出流水。
- 手续费：单独支出，不并入转移排除。
- 多渠道重复消费／退款：支付渠道和银行卡记录，等额、120 秒内、资金账户吻合、银行卡描述为支付记录且订单引用相同，自动只保留支付渠道记录。证据不完整时提示人工核对，暂时两条均计入。
- 退款：按退款到账月份抵减支出。原付款状态为“已退款／部分退款”时仍保留原支出，并提示检查独立退款记录，避免直接按全额扣减。关联到原消费可同步分类；手工修改退款分类后保留手工值。
- 失败、关闭、取消、未支付交易保留记录但不计收支。
- 同渠道重复导入：文件内容、渠道、账户和映射相同则不再次导入；重叠账单按交易编号和事件字段去重。无编号时按业务字段及文件内出现次数匹配；同一文件的两条完全相同记录不会被合为一条。无编号且账单信息变化的情况仍需人工核对。
- 当前一条流水最多关联一条其他记录。多次部分退款可分别设置为退款和相同分类，不必都关联原消费；退款计数不依赖关联。
- 已有关联要先解除，再修改类型或重新配对。解除后不会立即自动配回，需要用户核对两条记录。

“待确认”显示全部月份。方向不明的记录暂不计入；已知方向的疑似重复保留原计数，因此有待确认记录时，总览标为暂计结果。

## 文件与备份

- data/user/ledger.sqlite3：个人流水、账户、规则、导入报告、原始字段和来源行。
- data/user/originals/：按内容哈希保存的原始文件副本，不修改上传原件。
- data/user/backups/：下载数据库备份时留存的副本，以及恢复前自动保存的旧数据库。
- data/demo/：演示账本，独立于个人数据。

数据库备份包含原始行和文件名，但不包含原始文件二进制。完整备份／迁移时停止服务，再复制整个 data/user 目录。恢复只接受本工具同版本数据库，校验通过后先备份当前数据库再替换。备份是私有文件，按账单同等保管。

本目录 .gitignore 排除 data、日志、虚拟环境和缓存。原始账单不应放到 examples 或代码目录。

## 手动启动

电脑已有 Codex 的 bundled Python 时，双击启动器会自动使用它，无需安装 Streamlit。实现采用 Python 自带的本机 HTTP 服务加 SQLite，XLSX 依赖 openpyxl，PDF 依赖 pdfplumber；模型接口使用 Python 标准库，不需要安装 OpenCode 或模型 SDK。

普通 Python 环境（Python 3.10+），在本目录打开 PowerShell：

~~~powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
~~~

已有 bundled Python 可直接运行：

~~~powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" .\app.py
~~~

后台服务固定使用 http://127.0.0.1:8765，重复打开复用同一实例，不改变端口。直接运行 app.py 仅供调试，默认可尝试其他端口；后台任务使用 --strict-port 禁止切换。

~~~powershell
.\.venv\Scripts\python.exe app.py --port 8875 --no-browser
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
~~~

代码入口：app.py 是本机服务，importer.py 是文件读取，core.py 是统计与关联，ui.html 是操作界面。openpyxl 的读取方法参考其官方文档：https://openpyxl.readthedocs.io/en/stable/tutorial.html 。

## 持续可用修复（2026-10-01）

后台任务名称为 CodexLocalLedger，仅以当前登录用户的普通权限运行，只监听本机。已安装登录后自启、每日每分钟的恢复触发器、进程失败重启；任务没有运行时限。关闭启动窗口、网页或 Codex 不影响由 Windows 启动的后台服务。

本次修复了目录权限：仅给当前用户对本记账目录的继承修改权限，其他目录和其他账户的权限不变。权限原始备份保存在 data/runtime/permissions-before-20261001.txt。

- 日常打开：双击 start-ledger.cmd，或打开固定网页地址。
- 重新安装后台任务：双击 install-background.cmd。采用系统 WScript，不需要修改 PowerShell 执行策略。安装器会检查现有同名任务是否属于本项目。
- 停用并卸载后台任务：双击 uninstall-background.cmd，保留账单文件和数据库。
- 启动问题：查看 data/runtime/service.log、startup-error.log 和 host-vbs.log。日志不记录交易内容。
- 网页已经加载时，会每 15 秒检查连接，服务恢复后自动重新加载；服务重启导致旧令牌失效时也会重新加载。初次访问恰好处于恢复间隙时，稍后刷新或双击启动器。
- 电脑关机、休眠、退出 Windows 登录时，本地服务不能访问；恢复后任务会重新启动。固定端口被其他程序占用、Python 环境被移除、Windows 主动禁用后台任务等情况仍需处理，不能承诺任何条件下永不故障。

实测终止账本 Python 进程后，Windows 在约 51 秒内自动启动新进程，仍使用原地址；连续两次运行启动器没有生成新的服务进程。登录触发器已核验配置，未为了测试注销或重启电脑。


## PDF 账单导入

在“导入账单”直接选择 PDF。支持文字层的有边框和普通无边框表格；同结构跨页表格合并，不同结构的表格在下拉框中分别选择。表头须含可识别的日期、金额或收入／支出列。PDF 不使用人工表头行编号，但仍可核对并修改字段映射。

加密 PDF 可输入文件打开密码，再点击“填写密码后重新读取 PDF”。密码仅用于本次本机读取，不写入数据库、日志或模型请求。原始加密 PDF 原样保存，密码不随备份保存。

来源原始字段包含 PDF 页码和表内行号。无法提取表格的页面会提示核对；异常数据行列入错误报告。扫描件、乱码或非表格文件明确报错，不让模型猜测金额生成流水。导入前务必核对原件的交易笔数、日期、收支列与合计，避免遗漏页面。支持上限为 150 页、20 MB、十万行。

## 账单分析

“账单分析”可使用所选月份或全部月份：

1. 点击“生成本地分析”无需 API Key，也不联网，使用与总览相同的记账口径。
2. 如需模型分析，默认选择 OpenRouter 免费模型。点击官方链接申请自己的 API Key，填写到密码框；密钥仅用于单次请求，不写磁盘、数据库、日志、浏览器存储或下载报告。发送后清空。
3. 默认模型 openrouter/free，或刷新当前零价模型清单，选一个 :free 型号。正式发送前再次核验清单；请求限制输入、输出和单次请求价格为零，不自动改用付费型号。可能因额度、限流、零价供应不足或网络条件失败。
4. 点击“预览发送内容”，查看提供方、具体接口、模型与完整数据，然后勾选确认并点击“确认发送并分析”。预览十分钟有效、单次使用；数据变化后必须重新预览。失败重试也重新预览。
5. 仅发送白名单汇总：月份、笔数、收入、消费、退款、净支出、结余、标准分类合计、月度合计、转移／重复／待确认笔数。选择单月时，不发送其他月份；选择全部月份时趋势仅含最近十二个有记录月份，但总计覆盖全部。姓名、卡号、账户名、商户、备注、逐笔明细及原始文件均不发送。汇总金额仍是个人财务信息，受所选提供方隐私政策约束。
6. 分析结果为纯文本，可下载；它不会自动修改流水、分类、转移关联或金额。数据未确认时结果为暂计。下载文本按私有财务文件保存。

OpenCode Zen 已预设其公开 chat/completions 接口和经官方文档核验的免费型号。其免费层近期出现仅允许 OpenCode 客户端使用的限制，外部请求可能被拒绝；本工具不会伪装客户端或绕过限制。部分免费模型会使用输入改进模型，NVIDIA 免费试用型号明确不接受个人或保密数据，因此未加入 Zen 允许清单。Zen 的模型目录不提供价格字段，当前允许清单基于 2026-10-01 官方免费价格表，无法保证其后定价不变；需要可执行零价限制时使用默认 OpenRouter。

真实模型生成需要用户自己的密钥，当前未进行真实模型调用。已实测两个提供方的目录接口，分析的请求、响应、错误提示、密钥不落盘与确认流程使用模拟接口验证。

### 接口与扩展

所有本地 API 都需要网页的 X-Ledger-Token，模型调用只在 Python 后端进行。个人账本路径前缀为 /api/，演示账本为 /demo/api/。

- GET analysis/providers：接口预设及默认模型。
- POST analysis/models：{provider}，读取当前免费清单，不发送账单。
- POST analysis/local：{month}，本地分析。
- POST analysis/preview：{provider, model, month}，返回发送预览与一次性 consent_token。
- POST analysis/run：{consent_token, confirmed:true, api_key}，发送此前明确确认的汇总；不接受客户端指定任意账单内容或覆盖预览的提供方／模型。

PDF 提取入口 pdf_importer.py；分析入口 analysis.py；分析页面交互 analysis-ui.js。接口基于 chat/completions 格式，后续提供方须在 PROVIDERS 与免费校验逻辑中显式加入。

官方资料：[OpenRouter 免费路由](https://openrouter.ai/openrouter/free)、[免费型号](https://openrouter.ai/docs/guides/routing/model-variants/free)、[零价供应限制](https://github.com/OpenRouterTeam/docs/blob/main/guides/routing/provider-selection.mdx)、[OpenCode Zen 接口与隐私](https://opencode.ai/docs/zen/)、[OpenCode 免费层限制记录](https://github.com/anomalyco/opencode/issues/49592)、[pdfplumber](https://github.com/jsvine/pdfplumber)。

开发测试另外需要 requirements-dev.txt 中的 ReportLab 和 pypdf（仅生成模拟 PDF 与密码测试）；当前 bundled Python 已包含，无新增安装。新环境运行测试前可执行 python -m pip install -r requirements-dev.txt。

前端异步切换回归测试（另需 Node.js）：node tests/test_analysis_ui.cjs。
